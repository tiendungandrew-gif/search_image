# ADR-001 — Modular Monolith thay cho Microservices

## Trạng thái

Chấp nhận cho MVP · 2026-11-03 · Chưa triển khai. Thay đổi kiến trúc cần cập nhật [SAD](../architecture/SAD.md) và có evidence.

## Bối cảnh

Đồ án cần nhiều năng lực AI/retrieval nhưng nguồn lực phát triển/vận hành chưa xác định. P0 ưu tiên correctness, latency và reproducibility; chưa có bằng chứng cần scale riêng business services.

## Quyết định

Một backend codebase chia module typed ports/adapters. API và durable indexing worker là hai process riêng từ cùng codebase. PostgreSQL, Qdrant, MinIO là persistence services, không phải business microservices.

## Phương án đã cân nhắc

Microservices cho encoder/query/indexer/agent; một process làm cả request và durable jobs; modular monolith với worker process. Chọn phương án cuối.

## Lý do

Giảm service hops và deployment/test complexity, phù hợp phát triển từng phase; vẫn tách CPU/GPU-bound indexing khỏi request execution và cho phép thay adapter.

## Đánh đổi

Cần ngăn cross-module imports tùy tiện; API replicas có thể nhân đôi model memory. Scale từng module kém linh hoạt hơn services riêng; worker vẫn cạnh tranh tài nguyên nếu dùng chung device.

## Hệ quả

Prompt 03 tạo module boundaries và hai entrypoints khi phù hợp phase. Chỉ tách service sau profiling/operational evidence, không đưa network service mới chỉ vì có tên module. Liên quan FR-007, NFR-006/008.
