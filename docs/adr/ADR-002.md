# ADR-002 — Qdrant làm Vector Database

## Trạng thái

Chấp nhận theo stack baseline · 2026-11-03 · Exact service/client versions chưa pin.

## Bối cảnh

Cần cosine ANN, payload filters, stable image IDs và index version compatibility. Metadata transaction và quyền truy cập vẫn cần PostgreSQL.

## Quyết định

Dùng Qdrant, một collection cho một search-index/embedding manifest. Point ID = image UUID; d lấy từ checkpoint pinned/runtime manifest. PG active pointer là nguồn routing, request pin collection cụ thể.

## Phương án đã cân nhắc

FAISS local index; PostgreSQL vector extension; dedicated Qdrant. FAISS đơn giản cho offline nhưng cần thêm persistence/filter/serve logic; vector extension giảm số kho nhưng khác stack baseline và cần so capacity. Chưa có benchmark chứng minh lựa chọn nào nhanh hơn.

## Lý do

Phù hợp công nghệ đã yêu cầu; hỗ trợ UUID và payload retrieval theo [Qdrant points](https://qdrant.tech/documentation/concepts/points/), cấu hình dimension/metric tại [collections](https://qdrant.tech/documentation/manage-data/collections/).

## Đánh đổi

Thêm một persistence service và eventual consistency; ANN có thể mất neighbors, filter/selectivity ảnh hưởng latency. Không đồng nhất ANN neighbor recall với relevance Recall@10.

## Hệ quả

Adapter kiểm tra schema/manifest; HNSW/search settings được pin trong benchmark; upserts phải applied trước ready. Reindex collection riêng, PG authoritative hydration/reconciliation. Chi tiết [DATABASE_DESIGN](../architecture/DATABASE_DESIGN.md), FR-001/002/008/016, NFR-005/011.
